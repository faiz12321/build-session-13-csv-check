How to check a CSV file for mistakes with Python

Short answer

A CSV file is the plain text table a spreadsheet exports. If a row has fewer fields than the header, later values may appear under the wrong headings when an app imports it, and the file still looks fine at a glance. This lesson builds a small read-only Python tool that reports rows with a different number of fields than the header, blank lines, empty or repeated column names, a byte order mark and quoting that stops the parser. It shows how many problems it found and the first five of each kind.

Common mistakes

  1. Counting lines instead of rows. A quoted field can hold a line break, so one record can span two lines. The Python documentation says the line number it reports is not the same as the number of records. The practice file shows it.
  2. Trusting a row count. A reader can count rows without noticing that some have too few or too many fields. The first version in this lesson does exactly that.
  3. Assuming every file uses commas. Some exports use semicolons or tabs. The tool reads commas only and reports a possible problem when the header looks like one column with a different separator in it.
  4. Treating a pass as proof the data is right. These checks look at the shape of the file, not the meaning. A file can pass and still hold a wrong value.

Frequently asked questions

How do I check a CSV file for mistakes with Python?

Read the file with the csv module, compare the number of fields in each row with the header, and look for blank lines, repeated column names and a byte order mark. This lesson builds a small tool that does that.

Will this change my file?

No. The tool only reads the file. A test checks that one small test file has the same bytes and the same modified time before and after a run. That is the only evidence for this claim.

Why can the line count differ from the row count?

The Python documentation says a reader's line number is not the same as the number of records, because records can span several lines. A quoted field with a line break inside is one record on two lines.

Does it list every problem?

It counts every problem of the kinds it checks, but shows only the first five examples of each kind. Unclosed quotes and text after a closing quote stop the parser, so the tool reports the first of those and stops. It then shows no counts, because it did not finish reading the file.

What counts as a repeated column name?

Only an exact match. The names a and A, or a and a followed by a space, are treated as different. A blank first line is reported as having no header. A line holding only spaces is counted as a row with one field, not as a blank line.

Does it work with semicolon or tab separated files?

No. It reads commas only. When the header looks like one column but contains a semicolon, a tab or a pipe, it reports a possible problem so you know to check the separator.
